# Department of Unfinished Business

We fix small problems in open-source projects.

## What we do

We find a bug with a clear reproduction and no fix, a wrong line in the docs, or a warning nobody cleaned up. We write a patch and send it. Then we close the file.

One clerk staffs the Department. We know that is a small number.

## How a case works

1. **Intake.** A clerk runs into a problem.
2. **Inquiry.** For anything bigger than a typo, the clerk opens an issue and asks if a fix is welcome.
3. **Filing.** The clerk tests the patch, matches the project's style, and submits it.
4. **Resolution.** The maintainer merges the patch or declines it, or the clerk withdraws it. All three outcomes close the case.

Each case gets a number: `DUB-0001`, `DUB-0002`, and so on.

## Standing rules

1. We test every patch before we submit it.
2. We ask first on anything bigger than a typo.
3. We follow the project's style, even when we disagree with it.
4. We follow up once, politely. Then we leave the case alone.
5. When a maintainer says no, we close the case and move on.
